---
title: Сравнение с другими инструментами
description: Чем vue-why-render отличается от Vue DevTools и вкладки Performance в Chrome.
---

| Возможность | vue-why-render | Vue DevTools | Chrome DevTools (Performance) |
|---------|:-:|:-:|:-:|
| **Показывает, какой компонент перерисовался** | да | да (подсветка) | нет |
| **Называет конкретный проп / реф / поле стора** | да | нет | нет |
| **Вердикт «новая ссылка, то же значение»** | да | нет | нет |
| **Pinia: стор + поле + экшен** | да | частично (только стор) | нет |
| **Vue Router: называет изменившийся параметр** | да | нет | нет |
| **Проверки рендеров в тестах** | да | нет | нет |
| **Бюджеты рендеров (удобно для CI)** | да | нет | нет |
| **Сохранение / дифф / сравнение отчётов** | да | нет | нет |
| **Подсказки, что чинить** | да | нет | нет |
| **Флеймграф / CPU-профиль** | нет | да | да |
| **Профилирование памяти** | нет | нет | да |
| **Работает в проде** | нет | да | да |

**Vue DevTools** показывает, что компонент обновился, но не какая зависимость к этому
привела. Чтобы найти источник, всё равно приходится делить пропы пополам или расставлять
`watch`. `vue-why-render` называет источник сразу — это инструмент отладки, а не
универсальный профайлер.

**Вкладка Performance в Chrome** профилирует время CPU, отрисовку и раскладку. Она не скажет,
что `ProductCard` перерисовался, потому что `badge` — новый объект с тем же значением.
Используйте оба: Chrome — чтобы понять, *куда ушло время*, этот пакет — чтобы понять, *почему так вышло*.
