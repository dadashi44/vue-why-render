---
title: ИИ-агенты (MCP)
description: Дать ИИ-агенту спросить у запущенного приложения, какие компоненты перерисовываются и почему.
---

`vue-why-render-mcp` позволяет ИИ-агенту (Claude Code, Cursor и др.) спросить у запущенного приложения, какие компоненты перерисовываются и почему, снять базовый отчёт и сравнить после правки. Включите опцию в приложении (только dev), затем подключите сервер:

```ts
app.use(VueWhyRender, { mcp: true })  // Nuxt: whyRender: { mcp: true }
```

```bash
claude mcp add vue-why-render -- npx -y vue-why-render-mcp
```

Cursor, `.cursor/mcp.json`:

```json
{ "mcpServers": { "vue-why-render": { "command": "npx", "args": ["-y", "vue-why-render-mcp"] } } }
```

Откройте страницу в браузере и попросите агента вызвать `status`. Нужен Node 20 или новее.

Свой адрес моста в приложении: `mcp: { port: 7711, host: 'localhost' }`.

## Инструменты

| Инструмент | Что делает |
| --- | --- |
| `status` | Подключено ли приложение, заголовок страницы, URL, версии Vue и пакета. |
| `report` | Отчёт о рендерах: компоненты, счётчики, причины. Необязательные `limit` (1-100) и фильтр `component`. |
| `component` | Подробности об одном компоненте по `name`: инстансы, причины, изменения пропсов, подсказки. |
| `reset` | Обнуляет счётчики в приложении. |
| `baseline` | Сохраняет текущий отчёт, с которым потом можно сравнить, и обнуляет счётчики. |
| `diff` | Сравнивает текущий отчёт с базовым. Необязательный `limit`. |

Всё, что приходит со страницы (имена компонентов, значения, URL), оборачивается в блок `<page-data>` и помечается как данные, а не инструкции.

## Настройка

| Флаг | Переменная окружения | По умолчанию |
| --- | --- | --- |
| `--port <n>` | `VWR_MCP_PORT` | `7711` |
| `--host <host>` | `VWR_MCP_HOST` | `localhost` |
| `--allow-origin <host>` (можно повторять) | `VWR_MCP_ALLOW_ORIGIN` (через запятую) | нет |

Флаги важнее переменных окружения. Приложение должно использовать тот же порт: `mcp: { port }`.

Подключиться могут только страницы с `localhost`, `127.0.0.1`, `[::1]` и `*.localhost`. Если вы открываете приложение на другом хосте (адрес в локальной сети, туннель), добавьте его через `--allow-origin`.

Если порт занят (обычно другой сессией агента с этим же сервером), сервер всё равно запускается, и `status` сообщает об этом. Закройте другую сессию или выберите другой порт.

Сервер пишет в stdout только протокол MCP; логи уходят в stderr.
