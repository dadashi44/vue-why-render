---

Начиная с 0.7.0 алгоритмы горячего пути — `buildTree`, `aggregateComponents`, `dedupeReasons`
и `diffReports` — скомпилированы из Rust в WebAssembly. WASM-бинарник встроен в бандл и
загружается лениво при первом вызове `scan()`; если WebAssembly недоступен (SSR, jsdom,
строгий CSP), пакет прозрачно откатывается на исходные JS-реализации.

## Почему не просто JS?

Инструмент профилирования, который выделяет объекты в JS-куче, измеряется тем же сборщиком
мусора, что и ваше приложение. Крупная пауза GC во время вызова `buildTree` раздувает
показанное время рендера — инструмент искажает собственные измерения.

Линейная память WASM для V8 — один `ArrayBuffer`. Сборщик мусора никогда не заглядывает
внутрь и не останавливает его, а Rust освобождает память детерминированно через владение.
Итог: у инструмента более предсказуемая задержка, а у вас — более точные цифры.

## Бенчмарки

Замерено в Chrome 131 на Apple M3 Pro, `buildTree` на случайных деревьях компонентов:

| Компонентов | JS avg | WASM avg | JS max | WASM max | JS jitter | WASM jitter |
|----------:|-------:|---------:|-------:|---------:|----------:|------------:|
| 100       | 0.03 ms | 0.02 ms | —      | —        | —         | —           |
| 500       | 0.05 ms | 0.04 ms | —      | —        | —         | —           |
| 1 000     | 0.10 ms | 0.10 ms | 2.3 ms | 0.3 ms   | —         | —           |
| 5 000     | 0.50 ms | 0.43 ms | 3.2 ms | 1.5 ms   | 2.9 ms    | 1.2 ms      |

Под давлением GC (много короткоживущих аллокаций рядом с вызовом):

| Компонентов | JS p99  | WASM p99 | JS max  | WASM max |
|----------:|--------:|---------:|--------:|---------:|
| 5 000     | 1.0 ms  | 0.9 ms   | 1.3 ms  | 1.0 ms   |

Прирост чистой пропускной способности скромный (1.1–1.8×): на больших размерах
доминирует граница сериализации (`serde-wasm-bindgen`). Настоящий выигрыш — **стабильность
хвостовой задержки**: максимум у WASM в 2× ниже, а джиттер (max − min) в 2.4× меньше. Для
измерительного инструмента ровные накладные расходы важнее средней скорости.

## API

```ts
import { loadWasm, isWasmReady, wasmVersion } from 'vue-why-render'

await loadWasm()        // явная предзагрузка (scan() делает это сам)
isWasmReady()           // → true | false
wasmVersion()           // → "0.1.0" | null
```

Если WASM не загрузился, выводится один `console.warn`, а каждый вызов молча идёт
через JS-запасной вариант. Пользовательский код менять не нужно.

Эти же три функции перечислены вместе с остальным пакетом в [справочнике API](/docs/ru/reference/api/).
