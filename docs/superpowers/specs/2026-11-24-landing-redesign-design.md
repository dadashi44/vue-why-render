# Редизайн главной vue-why-render.js.org

Дата: 24 ноября 2026. Статус: на согласовании.

## Зачем

Главная выглядит как обычный одностраничник: заголовок, песочница и длинная инструкция по
установке, которая теперь есть в документации. Нужна главная, которая выглядит как сайт
продукта: шапка с навигацией, анимация, понятная история «увидел → понял → исправил →
закрепил». Плюс счётчик посещений: сейчас аналитики нет совсем.

Успех: человек с Хабра или GitHub за первый экран понимает, что делает инструмент, видит его
в действии, переходит в документацию или песочницу; автор видит, сколько людей пришло.

## Цели

- Новая главная по макету, выбранному пользователем: герой из варианта A, цепочка причины из
  варианта B, блок таймлайна «до/после» из варианта C. Исходники макетов лежат в репозитории:
  `docs/superpowers/specs/landing-mockups/a-hero.html` (шапка, герой, пять причин, путь, MCP,
  футер), `b-chain.html` (цепочка), `c-timeline.html` (таймлайн с переключателем). Это разметка
  холста дизайна (`.dc.html`: шаблон `{{ }}`, `<sc-for>`, класс `DCLogic`), не готовый код: брать
  из неё раскладку, размеры, тексты и keyframes, а не синтаксис. Онлайн-холст удаляется после
  реализации.
- Шапка на всех размерах экрана: логотип, Docs, Playground (якорь на песочницу), Case study
  (`cases/bigplay/`), Changelog (CHANGELOG.md на GitHub), выбор языка, GitHub.
- Три языка, как сейчас (en, ru, zh-CN), все новые тексты переведены.
- GoatCounter на главной, странице кейса и в документации.

## Не цели

- Переезд лендинга на Astro.
- Изменения в самой библиотеке, в документации (кроме подключения счётчика) и в странице кейса
  (кроме подключения счётчика).
- Новые картинки og:image.

## Анти-цели

- Сломать живую песочницу: настоящая панель vue-why-render продолжает сканировать демо.
- Шумная анимация: эффекты на каждом блоке, появление каждой секции при прокрутке.
- Анимация, которая не выключается при «уменьшить движение» в системе.
- Новые рендеры служебных компонентов в панели песочницы.
- Cookies и баннер согласия.

## Ограничения

- Vite-сборка `site/` (`npm run build:site`), `base` из `SITE_BASE`; документация собирается
  после неё в `dist-site/docs` — порядок и адреса не меняются.
- Язык переключается перезагрузкой с `?lang=` (язык панели задаётся при подключении плагина) —
  так и остаётся.
- Панель исключает служебные компоненты по `exclude: [/^Site/, 'App', 'Anonymous']`
  (`site/main.ts`): все новые компоненты лендинга называются `Site…`.
- Без новых зависимостей во время выполнения в корневом `package.json` (`dependencies`);
  dev-зависимости допустимы.

## Подходы

1. **Переделать `site/App.vue` и `site/styles.css` на месте, разбив страницу на компоненты
   `site/components/Site*.vue`; анимации на CSS.** — **Выбрано.** Сохраняет песочницу, i18n,
   кейс и сборку; анимация без библиотек.
2. Перенести лендинг на Astro рядом с документацией. — Отклонено: риск для песочницы без
   выгоды для внешнего вида.
3. Анимации на библиотеке (GSAP, motion). — Отклонено: всё нужное — циклы и появление по
   загрузке — делается на CSS keyframes; лишний вес.

Аналитика: GoatCounter (выбор пользователя) — бесплатен для open source, без cookies, данные
можно сделать публичными. Отклонено: Cloudflare Web Analytics (нужен аккаунт Cloudflare).

## Как устроено

### Порядок блоков

```
[шапка]
1. Герой — заголовок, подзаголовок, кнопки «Read the docs» / «Try it on this page»,
   строка установки с кнопкой копирования; справа окно магазина со вспышками и строками причин
2. Цепочка причины — cart.add(lamp) → cart.items → subtotal → <CartBadge>, бегущий сигнал
3. Живая песочница (существующая, id="demo")
4. Пять видов причин — prop / ref / computed / pinia / router, по строке примера
5. Таймлайн «до/после» с переключателем — данные кейса BIGPLAY
6. Путь: заметил → отчёт → тест → бюджет (нумерованный — это последовательность)
7. ИИ-агенты (MCP) — пример диалога, ссылка на страницу MCP в документации
[футер]
```

Блок «Установка и подключение» с полными примерами Vite/Nuxt уходит: он есть в документации;
на главной остаётся строка `npm i -D vue-why-render` в герое и ссылка «Read the docs».
Блок «Отчёты» (сравнение) переходит в таймлайн, «Возможности» — в «пять видов причин» и «путь».

### Внешний вид (как в макете A)

- Цвета существующие (`site/styles.css`): фон `#0d0f13`, поверхность `#14171d`, линия `#242933`,
  текст `#e6e8ec`, приглушённый `#949aa6`, акцент `#6ee7a8`. Оранжевый «горячих» компонентов —
  существующий `--warn: #f0a868` (в макете был `#ff8a5c`; берём существующий, чтобы совпадать
  с панелью и документацией).
- Шрифты: Onest (текст, с кириллицей) и JetBrains Mono (код, строки причин). Подключение — на
  выбор исполнителя: self-host через `@fontsource/*` (dev-зависимость) предпочтительнее Google
  Fonts (без запросов на сторонний домен).
- Шапка липкая, полупрозрачный фон с blur, на узком экране переносится в несколько строк
  (без бургер-меню). Выбор языка — существующая логика `switchTo`.
- Ширина контента 1200 px, отступы по краям 24 px, на телефоне без горизонтальной прокрутки.

### Анимация

- Герой: компоненты в окне магазина вспыхивают контуром по циклу (зелёный — обычные,
  оранжевый — горячий SearchBar с быстрым циклом); строки причин под окном появляются одна
  за другой один раз при загрузке.
- Цепочка: узлы по очереди загораются, по соединениям бежит сигнал, цикл ~6 с.
- Таймлайн: по дорожкам бежит вертикальная полоса; при переключении «Before fix / After fix»
  отметки рендеров плавно меняются (это ответ на действие).
- Больше ничего не анимируется: без появления секций при прокрутке и hover-эффектов на блоках.
- `prefers-reduced-motion: reduce` — все циклы выключены, всё видно в конечном состоянии.
- Окно магазина в герое — разметка-иллюстрация на CSS, не Vue-компоненты песочницы: анимация
  не вызывает рендеров.

### Таймлайн: реальные данные кейса

Цифры — из страницы кейса (`site/cases/bigplay/index.html`, блоки «до/после» кейсов 1, 2 и
шапки). Сценарии разные, поэтому дорожки сгруппированы с подписью сценария:

| Сценарий | Компонент | До | После |
|---|---|---|---|
| 60 секунд на главной | card | ×600 | ×10 |
| 60 секунд на главной | FinishOfRegistrationTimer | ×120 | ×2 |
| 10 смен query | ui-logo | ×20 | ×0 |
| 10 смен query | navbar | ×10 | ×0 |
| 10 смен query | footer | ×10 | ×0 |

Отметок на дорожке не больше ~40 (при большем числе — 40 и точный счётчик справа). Подпись под
таймлайном: «до» — итог «−98% renders, −98% time» и причина шапки из кейса (`route
query.utm_campaign`), «после» — «navbar, ui-logo, footer: ×40 → ×0». Ссылка «Read the case
study». Данные не выдумываются: только эти строки. *(Решение исполнителя.)*

### Тексты

- Заголовок сохраняет смысл нынешнего («See which components re-render — and why»).
- Все тексты — в `site/i18n.ts` (интерфейс `SiteMessages` расширяется, ненужные ключи удаляются),
  три языка. Строки кода и имена компонентов не переводятся.
- В шапке цифра звёзд GitHub не показывается (без запросов к API).
- Кейс только на русском: в en и zh подписи ссылок на кейс помечаются, как сейчас
  (`caseLink`: «case study (ru)», «案例（俄语）»). *(Решение исполнителя.)*

### GoatCounter

- Код сайта: `vue-why-render` (`https://vue-why-render.goatcounter.com`). Аккаунт создаёт
  пользователь.
- Скрипт: `<script data-goatcounter="https://vue-why-render.goatcounter.com/count" async
  src="//gc.zgo.at/count.js"></script>` — в `site/index.html`, `site/cases/bigplay/index.html`
  и в `head` Starlight (`docs-site/astro.config.mjs`).
- Один сайт GoatCounter на всё: главная, кейс, документация.
- Считаются только визиты на `vue-why-render.js.org`: localhost, github.io и превью не считаются
  (скрипт не подключается или не отправляет счёт, если `location.hostname` другой).
- Путь считается без query: `?lang=` не дробит статистику (язык не нужен в отчёте).
  *(Решение исполнителя.)*
