# Документация vue-why-render на Astro + Starlight

Дата: 24 ноября 2026. Статус: на согласовании.

## Зачем

README (`README.md` 757 строк, `docs/README.ru.md` 612, `docs/README.zh-CN.md` 576) — по сути вся
документация проекта, но он слишком длинный, и нужное в нём сложно найти. Нужна документация с
отдельными страницами, боковым меню и поиском, чтобы ответ на вопрос «как включить бюджеты»,
«как подключить MCP», «почему компонент перерисовался через computed» находился за секунды.

Успех: человек приходит с вопросом, за один-два клика или один поиск попадает на короткую
страницу с ответом и примером кода; на трёх языках.

## Цели

- Документация на `vue-why-render.js.org/docs/` — Astro + Starlight (меню, поиск, тёмная тема).
- Три языка сразу: английский (по умолчанию), русский, китайский. Тексты берутся из трёх README
  и раскладываются по страницам. Исключение — разделы, которых нет в `docs/README.ru.md` и
  `docs/README.zh-CN.md`: «WASM engine» (Why not just JS?, Benchmarks, API), «Compared to other
  tools», «FAQ», а также новая страница «Расширение VS Code». Их **переводим** на русский и
  китайский с английского (решение пользователя: все три версии документации полные, без
  английских заглушек).
- После переезда README на всех трёх языках сокращается до короткого введения, установки и
  ссылок на разделы документации.
- С лендинга и из README есть заметные ссылки на документацию.

## Не цели

- Переезд лендинга и страницы кейса на Astro (вариант Б) — возможно позже отдельной задачей.
- Живые Vue-примеры внутри документации — песочница уже есть на лендинге; в первой версии нет.
- Новый контент сверх README, кроме короткой страницы про расширение VS Code (оно вышло в 0.8.0,
  но в README не описано) — берётся из CHANGELOG 0.8.0 и `packages/vscode/README.md`.
- Версионированная документация (по версиям пакета).

## Анти-цели

- Сломать текущие адреса: `/` (лендинг с песочницей) и `/cases/bigplay/` (на него есть ссылки с
  Хабра) должны работать как раньше.
- Два расходящихся источника правды: после переезда README не дублирует документацию.
- Шаблонный вид Starlight по умолчанию: документация должна выглядеть частью проекта.
- Утяжелить установку основного пакета: зависимости Astro не попадают в его `dependencies`.

## Ограничения

- Хостинг — GitHub Pages через существующий `.github/workflows/pages.yml`, домен js.org
  (`vue-why-render.js.org`). `base` берётся из настроек Pages (`SITE_BASE`): на своём домене это
  `/`, на github.io — `/vue-why-render/`; документация живёт под `${SITE_BASE}docs/`.
- Vite-сборка сайта (`npm run build:site`) пишет в `dist-site/` с `emptyOutDir: true`, поэтому
  документация собирается после неё, в `dist-site/docs/`.
- Папка `docs/` в репозитории уже занята (переводы README, `logo.svg`, `demo.gif`, спеки) —
  Astro-проект живёт в другой папке.
- Node ≥ 20 (CI гоняет 20/22/24).

## Подходы (выбраны с пользователем)

1. **Где живёт документация.**
   - А. Раздел `/docs` на том же сайте; лендинг и кейс остаются на Vite. — **Выбрано.** Решает
     проблему поиска нужного с минимальным риском для существующего.
   - Б. Весь сайт на Astro. — Отложено: к поиску нужного ничего не добавляет, а лендинг придётся
     переносить.
   - В. Отдельный поддомен `docs.`. — Отклонено: отдельный деплой и запись в js.org без выгоды.
2. **Языки.**
   - Все три сразу. — **Выбрано**: тексты уже есть во всех трёх README.
   - Английский сразу, остальные позже. — Отклонено: русская аудитория (Хабр) осталась бы с
     длинным README.
3. **Движок** — Astro + Starlight (просьба пользователя «Astro + Vue»; Starlight даёт меню,
   поиск Pagefind без сервера, i18n). `@astrojs/vue` подключается, чтобы Vue-компоненты можно
   было добавить позже, но в первой версии не используется. *(Решение исполнителя.)*

## Как устроено

### Проект

- Папка `docs-site/` в корне репозитория — отдельный пакет со своим `package.json` и lock-файлом,
  как `packages/vscode` и `packages/mcp` (не npm workspace). Зависимости: `astro`,
  `@astrojs/starlight`, `@astrojs/vue`, `vue`.
- `astro.config.mjs`: `site: 'https://vue-why-render.js.org'`, `base` = `${SITE_BASE}docs`
  (по умолчанию `/docs` для локальной сборки), `outDir: '../dist-site/docs'`.
- Корневые скрипты: `docs:dev`, `docs:build` (`npm --prefix docs-site run build`); `pages.yml`
  после `npm run build:site` выполняет `npm ci --prefix docs-site` и `npm run docs:build` с тем
  же `SITE_BASE`. CI (`ci.yml`) собирает документацию, чтобы битая страница не доходила до `main`.

### Языки

- Starlight i18n: английский — корневой язык (`/docs/…`), русский — `/docs/ru/…`, китайский —
  `/docs/zh-cn/…`. Переключатель языков в шапке; поиск по каждому языку отдельно.
- Если страница на каком-то языке отсутствует, Starlight показывает английскую с пометкой — это
  допустимо только временно; в первой версии все страницы есть на всех трёх языках.

### Структура (меню)

Разделы README раскладываются так (одна страница — одна тема, ссылки внутри — относительные):

- **Начало**
  - Введение — что делает пакет, пример строки причины, возможности (из «Features»), ссылка на
    песочницу.
  - Установка — npm, установка с GitHub без npm.
  - Быстрый старт: Vue, Nuxt, вручную без плагина.
- **Руководства**
  - Панель и оверлей (пауза, сброс, фильтр, горячая клавиша, перетаскивание, тема).
  - Vue DevTools и Nuxt DevTools.
  - Pinia.
  - Vue Router.
  - Подсказки.
  - Отчёты: сохранить, открыть, печать в консоль, Markdown для issue, сравнение двух отчётов.
  - Проверки в тестах (`expectRenders`).
  - Бюджеты и падение CI.
  - Открытие файлов в редакторе.
  - ИИ-агенты (MCP).
  - Расширение VS Code.
- **Как это работает**
  - Как определяется причина.
  - Стоимость (влияние на приложение).
  - Движок WASM (зачем, бенчмарки).
- **Справочник**
  - Опции (таблица из «Options»).
  - API (`scan`, `getStats`, `getEvents`, `getReport`, `onRender`, `diffReports`, WASM API).
  - API для тестов (`vue-why-render/test`).
- **Ещё**
  - Сравнение с другими инструментами.
  - FAQ.
  - Чего пакет не делает.
  - Кейсы — ссылка на `/cases/bigplay/` (страница остаётся на лендинге).
  - Разработка и участие (из «Development» и «Contributing»).

### Внешний вид

- В стиле текущего сайта (`site/styles.css`): тёмная тема по умолчанию, фон `#0d0f13`, текст
  `#e6e8ec`, приглушённый `#949aa6`, акцент `#6ee7a8`, моноширинный шрифт как на сайте; через
  CSS-переменные Starlight (`--sl-color-*`), без своего шаблона. Светлая тема Starlight остаётся
  доступной переключателем. *(Решение исполнителя.)*
- Логотип и favicon — те же, что у сайта (`site/public/favicon.svg`, `docs/logo.svg`).
- Без признаков шаблонного дизайна: не добавлять градиенты, эмодзи, карточки-«фичи» на главной
  документации — главная документации это страница «Введение», а не второй лендинг.

### Связи

- Лендинг (`site/App.vue`): ссылка «Docs» / «Документация» / «文档» в шапке и в футере рядом с
  GitHub, на соответствующий язык документации.
- README ×3: короткое введение, демо-GIF, установка (`npm i -D vue-why-render`), минимальный
  пример Vue и Nuxt, ссылки на разделы документации на своём языке, лицензия. В английском README
  FAQ и «Compared to other tools» остаются кратко (одна-две строки со ссылкой) — их ищут в поиске
  GitHub/npm; в русском и китайском README таких разделов не было и не добавляется — только
  ссылки на соответствующие страницы документации. *(Решение исполнителя.)*
- `packages/mcp/README.md` получает ссылку на страницу MCP в документации.

## Проверка

- Сборка `npm run build:site && npm run docs:build` без ошибок и предупреждений о битых ссылках
  (Starlight проверяет внутренние ссылки при сборке — включить проверку, если есть опция; иначе
  — скрипт проверки ссылок в CI).
- После сборки в `dist-site/` есть и лендинг (`index.html`), и `cases/bigplay/`, и `docs/`
  (на трёх языках), и поиск работает в `astro preview`/статическом сервере.
- Ручная проверка: каждая страница из меню открывается на трёх языках, переключатель языков
  ведёт на ту же страницу, поиск находит «budgets» / «бюджет» / «预算».

## Релиз

- Один PR из ветки `feature/docs-site`; деплой происходит при мерже в `main` (pages.yml).
  Версия npm-пакета не меняется (сайт не входит в пакет).
- CHANGELOG `[Unreleased]` → «Изменено: документация переехала на vue-why-render.js.org/docs».
