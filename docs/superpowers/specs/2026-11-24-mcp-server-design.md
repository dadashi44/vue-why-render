# MCP-сервер для vue-why-render

Дата: 24 ноября 2026. Статус: на согласовании.

## Зачем

AI-агенты (Claude Code, Cursor, агенты сопровождения вроде того, что ведёт vase-ui) умеют замерить,
что страница стала быстрее, но не знают, **почему** компонент перерисовался: какой проп, реф,
computed или поле стора вызвало рендер. Без этого они гадают по коду. vue-why-render это знает.
Мейнтейнер vase-ui ответил на наш баг-репорт «most agents can benchmark this type of work really
easily» — MCP-сервер даёт агентам ровно то, чего у них нет: причину и подсказку, что исправить.

Успех: агенту говорят «посмотри, почему список тормозит при вводе», он вызывает инструменты
vue-why-render и получает ответ вида «`ComboboxItem` ×300 — `computed itemRoot`: новая ссылка,
то же значение; вынести …», а после правки сравнивает «до» и «после» одним вызовом.

## Цели

- Агент получает отчёт с причинами и подсказками из уже открытого приложения.
- Агент может начать замер с нуля, запомнить «до» и сравнить с «после».
- Подключение — одна команда в агенте и одна опция в приложении.
- Работает одновременно с расширением VS Code.

## Не цели

- Свой запуск браузера и сценарии (вариант Б) — у агентов есть свои браузерные инструменты
  (Playwright MCP, Claude in Chrome); можно добавить позже опцией.
- Документация на Astro + Vue — следующий отдельный шаг.
- Несколько вкладок/приложений одновременно в первой версии (см. «Решения строителя»).

## Анти-цели

- Серверные зависимости (`ws`, MCP SDK) не должны попасть в основной пакет `vue-why-render`.
- Мост не должен ломать или замедлять приложение, когда MCP не запущен (как сейчас мост VS Code:
  тихо переподключается раз в 3 с).
- Включение только явное (`mcp: true`) и только в разработке; в прод-сборку мост не уезжает
  так же, как сейчас весь пакет.
- Никаких изменений в поведении расширения VS Code и его порта 7710.

## Ограничения

- Браузер — клиент WebSocket, сервер — Node-процесс MCP (так же устроен мост VS Code).
- MCP-сервер общается с агентом по stdio (стандартный транспорт для `npx`-серверов).
- Основной пакет — ESM, Node-часть должна работать на Node ≥ 20.

## Подходы (выбраны с пользователем)

1. **Кто управляет страницей.**
   - А. Агент подключается к уже открытому приложению; кликают человек или браузерный инструмент
     агента, наш MCP объясняет. — **Выбрано.** Лёгкий, переиспользует мост, сочетается с любым
     браузерным инструментом.
   - Б. MCP сам запускает браузер через Playwright и прогоняет сценарии. — Отложено: тяжёлая
     зависимость и свой формат сценариев.
2. **Где живёт сервер.**
   - Отдельный пакет `vue-why-render-mcp` в `packages/mcp`, запуск через `npx`. — **Выбрано.**
     Основной пакет остаётся браузерной библиотекой. Имя в npm свободно (проверено 24.11.2026).
   - Команда в основном пакете. — Отклонено: серверные зависимости у всех пользователей панели.
3. **Как разойтись с VS Code.**
   - Свой порт 7711 и отдельный экземпляр моста. — **Выбрано.** Минимальная правка: `Bridge` уже
     принимает порт.
   - Один мост на несколько адресов. — Отклонено: переделка моста и расширения ради одного случая.

## Как это устроено

```
агент ⇄ (stdio, MCP) ⇄ vue-why-render-mcp ⇄ (ws://localhost:7711) ⇄ Bridge в браузере ⇄ Scanner
```

### Браузерная часть (основной пакет)

- Новая опция `mcp?: boolean | { port?: number, host?: string }` в `VueWhyRenderOptions`, дефолт
  `false`. При включении `scan()` создаёт второй `Bridge` с портом 7711 (рядом с `vscode`).
  Nuxt-модуль пробрасывает её без доработок (опции сериализуются целиком).
- `Bridge` учится отвечать на запросы. Сейчас команды — строка (`pause`/`resume`/`reset`).
  Добавляется сообщение `{ type: 'request', id, payload: { method, params } }` и ответ
  `{ type: 'response', id, payload }` (или `error`). Методы:
  - `report` → `getReport()` (тот же `Report`, что сохраняется в JSON, с причинами и подсказками);
  - `reset`, `pause`, `resume`;
  - `info` → URL страницы, заголовок, версия Vue и пакета, на паузе ли.
  Старые строковые команды остаются как есть — расширение VS Code не меняется.
- Чтобы ответить на `report`, мосту нужен доступ к `createReport`; мост получает колбэк
  `getReport` при создании (в `scan()` он уже есть у `handle`).
- Ещё метод `component` → `{ name }`: записи `registry.snapshot().records` с этим именем, по
  каждому экземпляру (uid, file, renderCount, updateCount, totalDuration, maxDuration,
  lastReasons, lastPropChanges) плюс подсказки `hintsForRecord`. Агрегированный `Report` для этого
  не годится: там экземпляры слиты по ключу `file::name`, а буфер событий ограничен 500.
  *(Решение Claude по итогам ревью.)*
- **Режим «только запросы».** Мост для MCP не подписывается на поток `snapshot`/`event`/`deps`
  (его использует только VS Code): MCP всё получает запросами. `Bridge` получает флаг режима;
  мост VS Code работает как раньше. Так включённый MCP не добавляет работы на каждый рендер.
  *(Решение Claude по итогам ревью.)*

### Серверная часть (`packages/mcp`, пакет `vue-why-render-mcp`)

- Бинарь `vue-why-render-mcp`: поднимает WebSocket-сервер на `localhost:7711` (порт и хост —
  флагами/переменными окружения) и MCP-сервер по stdio (`@modelcontextprotocol/sdk`).
- Держит последнее подключённое приложение; запросы шлёт ему с таймаутом.
- **Порт занят.** Агенты запускают по процессу на сессию, поэтому второй `vue-why-render-mcp`
  может не получить 7711 (EADDRINUSE). Такой процесс не падает: MCP-часть работает, а `status` и
  остальные инструменты отвечают «порт 7711 занят другим процессом vue-why-render-mcp (другая
  сессия агента?) — закройте её или задайте другой порт: `VWR_MCP_PORT` у сервера и
  `mcp: { port }` в приложении». Посредник между процессами — не в 0.1.0.
  *(Решение Claude по итогам ревью.)*
- **Кого пускать в WebSocket.** Подключение принимается только со страниц с `Origin` на
  `localhost`, `127.0.0.1`, `[::1]` и `*.localhost` (обычные dev-серверы); другие хосты dev-сервера
  (например `myapp.test`) — флагом `--allow-origin` / `VWR_MCP_ALLOW_ORIGIN`. Токена нет, опция в
  приложении остаётся одна. Всё, что приходит из приложения (имена, превью значений, URL), сервер
  отдаёт агенту как данные: в ответах инструментов оно явно помечено как содержимое страницы,
  а не инструкции. *(Решение Claude по итогам ревью.)*
- Форматирование для агента — текст/Markdown, а не сырой JSON: переиспользовать
  `formatReportMarkdown` и `formatDiff`/`diffReports` из основного пакета (подключить как
  зависимость или через отдельный безопасный для Node вход — решает строитель, см. ниже).

### Инструменты MCP

| Инструмент | Параметры | Что возвращает |
|---|---|---|
| `status` | — | подключено ли приложение; его URL, заголовок, версии, пауза |
| `report` | `limit?` (по умолчанию 20), `component?` (фильтр по имени) | топ компонентов по числу перерисовок: число, время, причины, подсказки |
| `component` | `name` | подробности по одному компоненту из живого реестра (метод моста `component`): по каждому экземпляру — счётчики, время, последние причины, изменения пропсов, подсказки |
| `reset` | — | счётчики обнулены, замер начат заново |
| `baseline` | — | текущий отчёт запомнен на сервере как «до» |
| `diff` | `limit?` | сравнение текущего отчёта с запомненным «до»: что ушло, что появилось, проценты |

Если приложение не подключено, любой инструмент кроме `status` возвращает понятную ошибку с
инструкцией: «Включите `mcp: true` в плагине и откройте страницу в dev-режиме».

### Подключение для пользователя

```bash
claude mcp add vue-why-render -- npx -y vue-why-render-mcp
```

```ts
app.use(VueWhyRender, { mcp: true })   // Nuxt: whyRender: { mcp: true }
```

## Тесты

- Мост: юнит-тесты на запрос/ответ (`report`, `component`, `reset`, `info`, неизвестный метод →
  ошибка), на то, что старые строковые команды работают как раньше, и на то, что в режиме
  «только запросы» мост не шлёт поток снапшотов и событий.
- Сервер: занятый порт (второй процесс не падает, `status` объясняет), отказ подключению с
  чужим `Origin`.
- `scan()`: при `mcp: true` создаётся мост на 7711, при `vscode` и `mcp` вместе — два моста.
- Сервер: тесты инструментов против фейкового клиента WebSocket (без браузера); таймаут, когда
  приложение не отвечает; ошибка, когда не подключено.
- Ручная проверка: песочница сайта + Claude Code с подключённым сервером, сценарий «найди,
  почему перерисовывается `ProductCard`».

## Решения строителя (не меняют того, что строится)

- Как Node-часть получает форматтеры из основного пакета (зависимость с безопасным входом или
  копия нужных функций).
- Несколько одновременно подключённых вкладок в первой версии: работать с последней подключённой
  и сообщать об этом в `status`.
- Таймаут запроса к приложению (порядка нескольких секунд).
- Где хранить `baseline`: в памяти процесса сервера.
